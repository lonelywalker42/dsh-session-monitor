# DSH Session Monitor 优化方案

## 已核实的运行环境（2026-10-03，北京时间）

| 实例 | 进程 | 监听端口 | 验证结果 |
| --- | --- | --- | --- |
| 桌面端监控 | DeepSeek Harness，PID 6284 | 127.0.0.1:8091 | `/api/state` 返回 3 个会话；Node v24.18.1 |
| webui 监控 | Node，PID 43920 | 127.0.0.1:8092 | `/api/state` 返回 0 个会话；Node v24.21.0 |
| webui 页面服务 | 同一个 Node 进程 | 127.0.0.1:3080 | 已确认监听；另有 0.0.0.0:3088 |

桌面 profile 显式配置 `port: 8091`，挂载的是 `D:/plugins/dsh-429-monitor-v1.1.0-dsh-desktop/dsh-429-monitor/host/session-monitor.mjs`；web profile 的包依赖来自 GitHub。当前工作区并不是桌面 profile 的加载路径。正在运行的桌面件可执行文件来自 web profile 安装目录，但它的 TCP 连接实际指向 8091；不能仅根据 exe 所在目录判断所属宿主。

8091/8092 是两个独立实例，不应合并或通过“扫描第一个在线端口”选择宿主。扫描会导致状态串线，消息可能投递到另一实例。

## 验证结果

npm test 全部通过：客户端 44 项、宿主 63 项断言，以及客户端运行时、双实例路由、设置迁移/投递回执、实际隔离 HTTP API、仪表盘生成脚本和真实 React 加载渲染测试。HTTP 测试使用随机空闲端口与临时数据，不操作真实会话；覆盖身份拒绝及同 requestId 只投递一次。

Windows exe 编译成功，PowerShell 脚本语法检查成功。共享 XAML 在当前 WPF 环境解析并完成前景布局测量：Panel 400×520、自动继续按钮 82×28、会话列表 370×294。完整离屏渲染程序仍因本环境 .NET Framework 启动错误 0x8007055A 失败，未生成 PNG；这些测量不能替代视觉验收。

已获准重试实机页面验收，再次打开隔离预览时自动审批服务返回 429 Too Many Requests，操作未执行。这是审批服务故障，不是风险判定；没有绕过审批。系统背景模糊、长会话卡片、拖动、键盘操作与 DPI 尚未实机验收。

隔离预览： http://127.0.0.1:18091 与 /popup，使用模拟会话。运行 npm run preview；npm run build:widget 编译 Windows 桌面件。node dev/render-widget.mjs 在正常 Windows/.NET Framework 环境生成前景 PNG，CI 运行结果待 GitHub 执行。

## 实际运行与后续验收

本轮再次确认桌面 8091、web 8092、webui 3080 仍由原进程监听。修改位于本仓库，尚未覆盖已安装插件或重启 DSH；当前 8091 页面因此仍是旧安装版本。没有向真实会话发消息，没有提交或推送 GitHub；远端实时状态仍未核验。

待验收：三处长标题、多会话滚动、等待/运行/完成/普通错误/限流/离线，浮窗收起与拖动，Windows 100%/150%/200% DPI、胶囊展开、模糊及高对比度回退，浏览器窄屏与键盘焦点。通过后用同一版本分别更新两处实际安装并在合适时机重启。

队列计时属于客户端，页面关闭暂停；宿主回执为内存且最多保存约 1000 条，重启后结果可能未知。自动继续去重亦非跨重启持久化。LH 自动 resume 有单独环境变量和次数上限，不属于会话继续开关。
